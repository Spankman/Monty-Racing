# One-time recovery-key backup — iPhone-friendly instructions

The recovery key is for research evidence. You will not need it for daily RM/C commands once private ticket delivery works. Do not paste it, photograph it or send it as a ChatGPT attachment.

Recommended: use an encrypted password manager you already trust, with a separate encrypted backup. No new paid service needed if existing storage is suitable.

1. Tell us **which existing secure store** you want to use and whether you have a trusted helper/computer available. Do not send passwords or key contents.
2. Approve one supervised transfer of the **existing** workspace key through that store’s authenticated secure-file route. A helper can handle the technical transfer. No key rotation or new account secret is needed for normal Actions encryption, which uses the public certificate only.
3. In your iPhone password-manager app, confirm the secure attachment is present. Save the encrypted backup separately (for example through a trusted helper to a separate protected device); do not leave the only backup on the same phone.
4. The authorised helper restores the backup in a private temporary environment and decrypts a **synthetic** test packet, checking certificate/hash/replay. You receive only a pass/fail receipt and date. The key/passphrase never appears in the report.
5. Keep access limited to you and specifically approved helpers. If you change the secure store, lose the phone or suspect compromise, stop new encryption until custody is reviewed. Rotation/revocation/expiry follow the [full procedure](../governance/RECOVERY_KEY_CUSTODY.md).
